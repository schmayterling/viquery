### RC-8 — high — job scheduling/retries — CONFIRMED

- id: RC-8
- severity: high
- category: catalog correctness / resource use
- file: `src/catalog/core.ts:353-355`; automatic caller `src/catalog/index.ts:32-39`
- summary: every folder rescan resets every terminally failed job in the library, so unrelated watcher events defeat the three-attempt retry limit.
- scenario: folder a contains a permanently failing visual job -> three failures, idle/failed. add healthy folder b -> a runs three more times. rescan unchanged b -> a runs three more times. repeated background updates in b keep restarting expensive failed work in a; thumbnail failures can repeatedly take priority over all visual/speech work.
- evidence: `/opt/homebrew/bin/node /tmp/red-codex/catalog-r3.mjs` uses real `Catalog.addFolder`, `rescan`, and `settled` with a deterministic failing compute boundary. observed failing calls 3 -> 6 -> 9; each settled job again says `attempts:3,state:'failed'`. folder b stayed healthy/done. reset SQL has no folder/media predicate and runs for automatic reconciliation too.
- fix direction: distinguish explicit retry from routine reconciliation; automatic scans should preserve terminal failures unless that media changes, and folder-scoped retries must only reset that folder's jobs.

### RC-9 — medium — video indexing correctness — CONFIRMED

- id: RC-9
- severity: medium
- category: catalog correctness / temporal indexing
- file: `src/compute/media.ts:143-145,164-172`; `src/compute/api.ts:116-121`; rejection `src/catalog/core.ts:872-881`
- summary: valid videos with long frame holds cannot be indexed: fixed ten-second windows without a decoded frame get samples from an earlier window, then catalog rejects the entire visual result.
- scenario: sixty-second h264 video at 1/20 fps (three frames held for twenty seconds each) -> six scene windows; windows 10–20s, 30–40s, and 50–60s receive sample timestamps 0s, 20s, and 40s respectively. all three visual attempts fail; video stays visible as a thumbnail but never gains searchable scenes/vectors.
- evidence: fixture `/tmp/red-codex/r3-media/sparse-frames.mp4` is 4,435 bytes, generated by `/tmp/red-codex/prepare-r3.mjs`. `node /tmp/red-codex/compute-r3.mjs visual /tmp/red-codex/r3-media/sparse-frames.mp4` returns six scenes/eighteen samples, nine outside their scene windows. real `Catalog` + real compute (`... catalog ...`) emits `invalid sample timestamp` three times and settles `{phase:'idle',items:1,failed:1}`, `scenes:[]`; logs `sparse-{visual,catalog}-r3.log`.
- fix direction: account for displayed frame intervals when building/sampling windows; make long-held frames represent their later windows without returning out-of-window sample timestamps.

### RC-10 — medium — search quality / false speech — CONFIRMED

- id: RC-10
- severity: medium
- category: search quality / transcript integrity
- file: `src/compute/media.ts:475-489`; `src/ml/index.ts:143-169`; `src/compute/api.ts:138-145`
- summary: non-speech audio passes the energy-only gate and becomes confident searchable transcript text.
