answer: yes. framescout, videohighlighter, videoseek, and scm already implement substantial parts of local semantic video search. ente and immich supply stronger operational references for paired encoders and background indexing, but their audited video search indexes one still per asset. reuse permissive components and proven patterns; viquery's useful work is reliable offline indexing, moment coverage, bounded cpu work, and measured retrieval quality/latency.

four requested implementations:

framescout

- flow: tauri/rust desktop coordinates separate python inference worker. image is a single sample at timestamp 0; video yields sampled rgb frames, processed in batches of at most 16. each retained frame gets one l2-normalized 768-d siglip2 image vector, optional ocr lines/text, and bge-m3 dense encoding of that text when available. no scene-level temporal encoder or scene-vector pooling in traced path. [server.py:55–146](https://github.com/bobgsning/FrameScout/blob/517de4b51a3fcb0f0c89aace14deb33bd3707542/src/inference-worker/server.py#L55), [siglip_engine.py:48–87](https://github.com/bobgsning/FrameScout/blob/517de4b51a3fcb0f0c89aace14deb33bd3707542/src/inference-worker/engines/siglip_engine.py#L48).
- sampling is more specific than “scene detection”: opencv seeks by frame number at quarter-second probes, comparing candidate with last retained frame, not immediately preceding decoded frame. grayscale mean absolute pixel difference >=25 retains frame immediately; <2.5 skips it; otherwise retain after one second since last retained sample. first frame always retained. limits: 3,600 retained frames or 3,600 seconds, so hour-long coverage can end earlier when many change probes survive. this is sampled change detection, not complete shot segmentation. comments mentioning similarity 0.98 are superseded by executable 0–255 difference thresholds. [video_extractor.py:34–145](https://github.com/bobgsning/FrameScout/blob/517de4b51a3fcb0f0c89aace14deb33bd3707542/src/inference-worker/media/video_extractor.py#L34), [config.py:29–54](https://github.com/bobgsning/FrameScout/blob/517de4b51a3fcb0f0c89aace14deb33bd3707542/src/inference-worker/config.py#L29).
- models: google/siglip2-base-patch16-256, separate siglip2_vision.onnx and siglip2_text.onnx, float32 image input 256², 768-d outputs; `AutoProcessor` image preprocessing, text padded to 64 token ids; exported opset14 and l2 norm in graph. optional `BAAI/bge-m3`: 1,024-d cls dense, max512 tokens, batch8; exporter stores its backbone fp16. rapidocr runs pp-ocrv4 detection/classification/recognition, default chinese+english weights supplied by wheel; language packs configurable. no asr or generated-caption indexing found after searching traced inference/search code. [download_models.py:75–165](https://github.com/bobgsning/FrameScout/blob/517de4b51a3fcb0f0c89aace14deb33bd3707542/scripts/download_models.py#L75), [download_models.py:201–278](https://github.com/bobgsning/FrameScout/blob/517de4b51a3fcb0f0c89aace14deb33bd3707542/scripts/download_models.py#L201), [config.py:60–71](https://github.com/bobgsning/FrameScout/blob/517de4b51a3fcb0f0c89aace14deb33bd3707542/src/inference-worker/config.py#L60), [ocr_engine.py:1–18,134–160](https://github.com/bobgsning/FrameScout/blob/517de4b51a3fcb0f0c89aace14deb33bd3707542/src/inference-worker/engines/ocr_engine.py#L1).
- size evidence: upstream siglip2 base checkpoint is 375,234,050 parameters / 1,500,985,224-byte safetensors, not a tiny mobile model; bge-m3 upstream onnx external weights are 2,266,820,608 bytes. these are upstream artifacts, not measurements of framescout's separate exports. exact exported sizes/ocr weight sizes unverified. [siglip2 metadata](https://huggingface.co/api/models/google/siglip2-base-patch16-256), [pinned checkpoint](https://huggingface.co/google/siglip2-base-patch16-256/blob/3f9f96cb90da5dbc758b01813f2f6f1aee24c1ab/model.safetensors), [bge files](https://huggingface.co/BAAI/bge-m3/tree/5617a9f61b028005a4858fdac845db406aefb181/onnx).
- storage/query: sqlite frame_vectors stores path/timestamp/vector_f32, with older json fallback; loaded into contiguous in-memory `FlatVectorMatrix`. rayon dot products across normalized vectors, full descending sort. ocr lines and bge vectors are separate tables. fts5 trigram table targets text_entries, not automatically a fused video transcript index. [db.rs:142–227](https://github.com/bobgsning/FrameScout/blob/517de4b51a3fcb0f0c89aace14deb33bd3707542/src/FrameScout-UI/src-tauri/src/storage/db.rs#L142), [vector_matrix.rs:68–84](https://github.com/bobgsning/FrameScout/blob/517de4b51a3fcb0f0c89aace14deb33bd3707542/src/FrameScout-UI/src-tauri/src/storage/vector_matrix.rs#L68), [migrations.rs:365–470](https://github.com/bobgsning/FrameScout/blob/517de4b51a3fcb0f0c89aace14deb33bd3707542/src/FrameScout-UI/src-tauri/src/storage/migrations.rs#L365).
- unified query -> siglip2 text encoding -> every frame cosine plus literal ocr/note/filename token matching. score is raw visual cosine when >0.001, otherwise count of literal-hit channels; bge search is explicitly excluded from this unified command. no learned reranker/rrf there. sort all hits, retain highest-scoring frame per file; returned timestamp is that frame, not multiple start/end moments. [search_unified_cmd.rs:8–13,43–166](https://github.com/bobgsning/FrameScout/blob/517de4b51a3fcb0f0c89aace14deb33bd3707542/src/FrameScout-UI/src-tauri/src/commands/search_unified_cmd.rs#L43); separate bge query scans media_text_vectors [search_cmd.rs:439–520](https://github.com/bobgsning/FrameScout/blob/517de4b51a3fcb0f0c89aace14deb33bd3707542/src/FrameScout-UI/src-tauri/src/commands/search_cmd.rs#L439).
- reuse: streaming/batched inference, per-frame timestamp+ocr provenance, sqlite binary-vector layout, explicit offline model loading. weak for viquery: repeated random seeks, arbitrary hour/frame truncation, last-kept comparison called scene detection, full-sort scans, file-level collapse discarding other moments, large second text encoder, mixed literal/cosine ordering. copy focused apache components; do not inherit whole stack.

videohighlighter

- distinguish two flows: semantic visual scan operates on a current video; highlight editor scores signals and selects clips. neither should be described as one prebuilt global semantic moment database. semantic model is openai/clip-vit-base-patch32, 512-d, 224²; pytorch `CUDA/DirectML` where selected, openvino export for intel/cpu fallback. upstream fp32 checkpoint is 605,247,071 bytes; packaged ir size unverified. [clip_prefilter.py:47–62,258–277](https://github.com/Aseiel/VideoHighlighter/blob/3a20f43fb7beff44822e0edba3fca9f706487718/llm/clip_prefilter.py#L47), [clip_index.py:43–50,336–339](https://github.com/Aseiel/VideoHighlighter/blob/3a20f43fb7beff44822e0edba3fca9f706487718/llm/clip_index.py#L43), [upstream checkpoint](https://huggingface.co/openai/clip-vit-base-patch32/tree/3d74acf9a28c67741b2f4f2ea7635f0aaf6f0268).
- frame sampling: standalone build_index sequentially decodes video, retaining every round(fps*interval) frame; default interval1s,batch16. interactive scan instead seeks missing timestamps on fixed lattice from zero; cached timestamp embeddings avoid repeated encoding. no scene pooling or near-identical-frame dedup in this semantic index; timestamp dedup only. [clip_index.py:211–234,342–402](https://github.com/Aseiel/VideoHighlighter/blob/3a20f43fb7beff44822e0edba3fca9f706487718/llm/clip_index.py#L342), [llm_chat_widget.py:335–442](https://github.com/Aseiel/VideoHighlighter/blob/3a20f43fb7beff44822e0edba3fca9f706487718/llm/llm_chat_widget.py#L335).
- search: encode positive query + three generic negative prompts; normalized dot products times logit_scale (default100), softmax across labels, take positive label score. without negatives query_vector maps cosine from [-1,1] to [0,1]; this is not calibrated confidence. default interactive top30. clip-only results emitted chronologically as timestamp points; clip+llm sends top-k frames to configured local vlm for contains_target confirmation. captions/analysis are query-time results, not persistent caption embeddings. no transcript/ocr/fts fusion found in clip_index/clip_prefilter. [clip_prefilter.py:262–268](https://github.com/Aseiel/VideoHighlighter/blob/3a20f43fb7beff44822e0edba3fca9f706487718/llm/clip_prefilter.py#L262), [clip_index.py:57–68,238–267](https://github.com/Aseiel/VideoHighlighter/blob/3a20f43fb7beff44822e0edba3fca9f706487718/llm/clip_index.py#L238), [llm_chat_widget.py:499–559](https://github.com/Aseiel/VideoHighlighter/blob/3a20f43fb7beff44822e0edba3fca9f706487718/llm/llm_chat_widget.py#L499).
- storage: compressed npz of float32 timestamps + fp16 embeddings (~1,024 bytes/frame before compression), metadata format/model/size/mtime/interval; cache filename hashes absolute path+size+mtime, not file contents. source uses np.load(`allow_pickle=True`) plus restricted eval of stored metadata; do not copy this cache trust boundary. [clip_index.py:71–79,269–317](https://github.com/Aseiel/VideoHighlighter/blob/3a20f43fb7beff44822e0edba3fca9f706487718/llm/clip_index.py#L269). analysis/transcripts/scenes live separately in json caches [video_cache.py:26–99,140–164](https://github.com/Aseiel/VideoHighlighter/blob/3a20f43fb7beff44822e0edba3fca9f706487718/modules/media/video_cache.py#L26).
- shot detector: every fifth decoded frame, half-resolution by function defaults; grayscale mean absolute difference. function default threshold50, main pipeline passes70 unless configured. after whole pass, if <0.5 cuts/min and >=120 samples, try median +4*1.4826*mad; reject derived threshold if <1.25*median or fails to add cuts. strongest-first adjacent suppression enforces0.5s separation; edges create complete [0,duration] scene spans. this detector does not drive clip lattice sampling. [motion_scene_detect_optimized.py:21–33,118–127,330–337,430–439](https://github.com/Aseiel/VideoHighlighter/blob/3a20f43fb7beff44822e0edba3fca9f706487718/modules/segments/motion_scene_detect_optimized.py#L21), [pipeline.py:927–941](https://github.com/Aseiel/VideoHighlighter/blob/3a20f43fb7beff44822e0edba3fca9f706487718/pipeline.py#L927), [scene_cuts.py:57–89,100–167](https://github.com/Aseiel/VideoHighlighter/blob/3a20f43fb7beff44822e0edba3fca9f706487718/modules/segments/scene_cuts.py#L57).
- other models/signals: whisper configurable, helper default small but shipped config disables transcription and selects base; local whisper.load_model, `cpu/CUDA`, beam1. optional actions use siglip2-base-patch16-256 (768-d); trained-action route has 5s windows at2.5s stride, four frames and per-person crops, optional trained head; object/face stacks are separate. these are optional signal pipelines, not embeddings in the clip npz. [transcript.py:207–250,290–315](https://github.com/Aseiel/VideoHighlighter/blob/3a20f43fb7beff44822e0edba3fca9f706487718/modules/audio/transcript.py#L207), [config.yaml:55–74](https://github.com/Aseiel/VideoHighlighter/blob/3a20f43fb7beff44822e0edba3fca9f706487718/config.yaml#L55), [frame_encoder.py:65–81](https://github.com/Aseiel/VideoHighlighter/blob/3a20f43fb7beff44822e0edba3fca9f706487718/modules/vision/frame_encoder.py#L65), [action_siglip.py:1–20,60–67](https://github.com/Aseiel/VideoHighlighter/blob/3a20f43fb7beff44822e0edba3fca9f706487718/modules/vision/action_siglip.py#L1). optional `VLMs/heads/detectors` vary by user installation; no fixed total model download size.

- reuse conceptually: immutable sample lattice, resumable per-timestamp memo, clip shortlist before expensive vlm, separate analysis from scoring. weak: per-video `UI/workflow`, query-dependent softmax, no global hybrid index, unsafe cache loading, size/mtime identity, expensive model zoo. agpl code excluded from mit-only copying.

recommended viquery pipeline — design proposal, not measured implementation

1. model and worker boundary. start evaluation with explicitly mit [laion openclip `ViT-B-32/laion2B-s34B-b79K`](https://huggingface.co/laion/CLIP-ViT-B-32-laion2B-s34B-b79K),512-d, paired image/text exports; compare permissive siglip2 only with actual `CPU/quality` measurements in research/models.md. no apple weights under current rule. export/provision exact artifacts+tokenizer+preprocessing as one versioned manifest, sha256 all bytes; package or explicitly fetch once. cache miss during indexing/search is local “model missing”, never automatic network. retain original portable model and runtime/device-specific optimization cache separately. one utility inference process, one model owner, serial image batches, query work prioritized between batches; start intra1–2/inter1 and one video job, measure rather than consume every core. runtime/provider choices belong to separate platform/runtime audit.

2. images. content hash -> trusted metadata/decode boundary -> apply `orientation/ICC`->srgb -> matched artifact resize/crop/channel/normalization -> one unit image vector + thumbnail. image timestamp absent/null, not fake video time0. schema separates asset, frame/sample, moment, text span, embedding generation, path alias and job state. artifact fingerprint includes weights, tokenizer, preprocessing and segmentation version; equal vector dimension never implies compatibility (immich evidence above). no caption model required for core semantic search.

3. video segmentation. prototype with native ffmpeg scene detection, avoiding python packaging: sequential decode, scale analysis output so longer edge<=384px (initial policy), evaluate select scene score on full decoded cadence; collect actual pts cuts where score>0.3, add0 and duration, collapse candidates<0.5s by strongest score. record threshold/analysis geometry as indexing version. ffmpeg n8.0 algorithm is clipped min(mafd,abs(mafd-prev_mafd))/100, score[0,1], not plain image difference, not probability. official docs recommend starting0.3–0.5 [f_select.c:282–311](https://github.com/FFmpeg/FFmpeg/blob/n8.0/libavfilter/f_select.c#L282), [filters.texi:31698–31704](https://github.com/FFmpeg/FFmpeg/blob/n8.0/doc/filters.texi#L31698), [rolling filter docs](https://ffmpeg.org/ffmpeg-filters.html#select_002c-aselect). explicit0.5s/scale policy needs calibration; hard cuts below0.5s can be merged and fades can be missed. evaluate montage, flash, dissolve, pan, screen recording, black frames, hdr and vfr cases before fixing defaults.

4. alternative scene implementation: pyscenedetect0.7.1 `ContentDetector` is adjacent-frame hsv difference, component weights hue/saturation/luma1 each,edges0; threshold27,min_scene_len15 frames defaults. `AdaptiveDetector` uses rolling `ContentDetector` baseline,ratio3,window2,min_content15 and helps camera motion. threshold27 is not equivalent to ffmpeg0.3. use official algorithm/test behavior as reference; add python dependency only if measured shot quality warrants it. [versioned algorithm docs](https://www.scenedetect.com/docs/0.6.4/api/detectors.html), [0.7.1 current docs](https://www.scenedetect.com/docs/latest/api/detectors.html). ffmpeg path is smaller initial deployment; no claim it segments semantic events perfectly.

5. representatives and coverage. every detected shot gets at least one sample. split shots longer10s into bounded windows so locked-off hour footage still has coverage. for <=2s window embed midpoint only; otherwise20/50/80% frames (max3). preserve sample pts and enclosing shot/window start/end. include first/last shot regardless cut count; no per-video total cap that silently drops tail. simplest prototype uses second sequential decode to select planned samples instead of n independent seeks; cost table below includes both decode passes. later one shared decode with bounded lookback can halve decode cost if profiling justifies it. nearest decoded pts is authoritative; do not derive timestamps from frame ordinal/nominal fps for vfr.

6. pooling and dedup. retain each representative vector; score moment by max image-query cosine over its representatives, with winning sample timestamp as seek anchor. do not replace them by mean: rare object/action can disappear into scene average; max has own bias toward moments with more samples, bounded by same1/3 sampling policy. initially no additional pooled vector. if vector count demands coarse candidate stage, add normalized mean scene vector plus member-frame rerank; measure recall against exact per-frame baseline before relying on pool alone. videoseek's median is an alternative to test, not proof it is superior.

7. dedup before encoder. exact hash of model-input pixels can reuse embedding globally while preserving every (asset,pts,moment) occurrence. optional adjacent-within-shot near-duplicate gate:64-bit dhash<=4 plus small per-channel mean-color difference (initial8/255 policy), preserving at least one representative/window; retain alias span/time rather than delete moments. momentsearch supplies tested small implementation of dhash+luma idea; luma-only cannot distinguish some flat colors. where ocr matters, do not discard changed text based only on image hash similarity; exact-match reuse is safe default until text-sensitive recall measured. file/content dedup is separate from perceptual-frame dedup.

8. text stage. metadata/filename first; local ocr on representative stills when enabled; local asr timed cues ->~20s or sentence-bounded text spans, preserving original start/end and language. run as resumable lower-priority stage, show coverage. optional local caption generator later writes caption+source model+sample/moment range; cpu baseline does not caption every frame. no network `ASR/VLM/diarization`. populate sqlite fts5 over `captions/transcripts/OCR/metadata`; chunk text by actual timestamps, link overlap to moments without broadening a2s cue into unrelated10s content. captions/transcripts absent or unfinished is visible state, not “no match”.

9. query. normalize/filter -> warmed text encoder -> top~200 frame candidates and independently top~200 `FTS5/BM25` hits -> canonicalize each branch to moment ids using best matching member/overlap -> rank branches -> rrf sum1/(60+rank), rank starts1. same moment receives at most one vote from visual branch and one from lexical branch; repeated captions/frames do not inflate rank. provenance and raw branch scores retained. use primary rrf paper [cormack, clarke, büttcher, sigir2009](https://cormack.uwaterloo.ca/cormacksigir09-rrf), not incompatible raw cosine+bm25 units. fts5 bm25 ranks lower values as better; parameterize lexical queries, escape fts syntax as data [official fts5](https://sqlite.org/fts5.html#the_bm25_function). no learned reranker on latency-critical baseline. optional small text cross-encoder can rerank only text-bearing shortlist when measured benefit exceeds `CPU/latency` cost; it cannot judge uncaptioned motion.

10. results. image card -> asset; video card -> {asset_id,moment_start_ms,moment_end_ms,seek_ms,winning_frame,matched_text_spans,source_scores}. allow multiple distinct moments/video. merge adjacent returned windows only within same shot when both match; cap displayed span, do not merge across cuts merely because within15s. collapse repeated neighbor results using interval overlap/temporal nms while retaining separate occurrences. exact dialogue query anchors actual cue; visual query anchors best frame. show similarity/provenance, not probability. rejection threshold is model/calibration-specific; ente0.175 cannot be transferred to another checkpoint.

11. storage and search scale. sqlite single writer owns durable asset/job/sample/moment/text rows and fts updates in bounded transactions; external workers submit results. persist vectors as compact float32 + explicit model generation. exact native search is correctness baseline: sqlite-vec is a small c extension with vec0,float/int8/binary vectors and metadata/partition columns, currently pre-v1; `API/version/package` verification belongs to platform slice [official sqlite-vec](https://github.com/asg017/sqlite-vec). native scan or contiguous native matrix avoids js per-element loops; exact method still o(nd). use measured native baseline first; add ann only when p95 budget fails at intended vector count, retain exact rerank and recall comparison. clip-retrieval shows faiss path for scale but not necessity at100k.

12. incremental/resumable identity. initial stat gates expensive read; new/changed files get full-file sha256, not rclip partial hash nor path/mtime identity. stable asset key=(content_sha256); path aliases survive rename. stable sample key=(asset_hash,pts,preprocess/model generation), moment key includes segmentation generation. before/after stat detects file changed while hashing/indexing; publish complete generation transactionally, keep prior generation visible until replacement ready. jobs persist stage/checkpoint/error; unique upserts/readback make retry idempotent, restart computes missing records. file removal removes alias; content garbage collection only after no aliases and explicit policy. retain timestamps even when vectors shared. model swap enqueues new generation; stale worker output rejected by generation check.

cpu cost per hour — explicit arithmetic, not benchmark claim

no target-machine benchmark performed. parent model audit may supply measured encoder numbers; substitute those for l below. estimates exclude `ASR/OCR/captioning`, thumbnail encoding, storage/hash `I/O`, thermal throttling and contention unless added explicitly.

- 1h30fps video =108,000 decoded frames per complete pass; sequential two-pass prototype decodes216,000. low-res analysis reduces `filtering/IPC`, not necessarily codec decoding cost.
- no cuts:360 ten-second windows*3 samples=1,080 embeddings/hour. six-second average shots:600*3=1,800. half-second rapid cuts:7,200*1=7,200. these are workload scenarios, not observed shot distributions; near-duplicate reuse can reduce actual inference count without removing moment coverage.
- let r=decode+scale+scene-analysis throughput as multiples of real time per pass, l=image inference milliseconds/sample, n=retained samples. serial wall seconds/hour approx7200/r + n*`L/1000` + hash/database/thumbnail costs. measuring both decode passes independently is better when sample extraction pass has different cost. output preview and search stay responsive because work is off main thread, not because indexing is cheap.

| assumed measured inputs, illustrative only | two decode passes | 1,800 embeds | subtotal/hour |
| --- | ---: | ---: | ---: |
| r20x, l15ms | 360s | 27s | 6.45min |
| r5x, l60ms | 1,440s | 108s | 25.8min |
| r1x, l200ms | 7,200s | 360s | 126min |

do not assign these rows to m2 or four-core x86 without measurement. “~6–26min/hour” is only conditional on achieving5–20x decode and15–60ms/sample. full-rate `HEVC/4K/software` decoding or heavy encoder can exceed real time. one-pass reuse would change7200/r to3600/r, saving3–60min in rows above; implement only after profile establishes decode bottleneck. cpu core-seconds must be reported separately from wall time; thread limits alone do not establish actual core utilization.

text costs add linearly: asr real-time factor0.1/0.5/1.0 would add6/30/60min per hour of audio (illustrative ratios, not model measurements). ocr1,800 reps at assumed50ms adds90s; caption600 moments at assumed1–5s each adds10–50min. this is why caption-all-frames and large vlm confirmation are excluded from baseline. models, decoder, `ASR/OCR/caption` components must each be timed on same machine/media.

search capacity:100,000*512*4=204,800,000 bytes (195.3mib) raw vectors, plus row `ids/index/metadata/FTS`. one exact scan reads `about205MB/query`;100ms implies at least~`2.05GB/s` effective read throughput before text `encoding/top-k/IPC`, so sub100ms is plausible engineering target but unverified. 100k assets is not100k vectors:100k one-hour videos at1,800 reps would be180m vectors/~369gb raw; ann alone does not fix `indexing/storage/UI` scale. benchmark against vector count, duration mix and resident memory, and name capacity boundary explicitly.

verification needed before adopting recommendation: fixed small corpus with short transient events, same scene repeated, speech-only hit, fine ocr, long static take, hard cut/dissolve/flash, `VFR/HDR/rotated` media. annotate timestamp intervals and compare per-frame exact retrieval vs proposed sampling/pooling at recall@k and moment overlap. on m2 cpu-only and four-core x86, separate cold model/load, steady encoder, decode passes, full index throughput, resume correctness and concurrent-query p50/p95 over repeated runs. test100k vectors and realistic image/video mix; include text encoding+fts+fusion+ipc in100ms target. no observed guarantee yet for “blazing fast”, cross-platform packaging or action understanding.

decision: reuse scm/rclip permissive desktop and image machinery selectively; adapt small apache momentsearch fusion/dedup concepts with full coverage/stable ids; use ente/immich as operational design evidence. build timestamped, resumable image-vector+fts moments first. true temporal action recognition, universal short-event recall and optional captions remain separate measured upgrades, not claims inherited from still-image clip.
